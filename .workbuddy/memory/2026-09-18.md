### 🔴 大坑：.env 的 DATABASE_URL 指向原库（BUG-008）

- `backend/.env` 从原项目 1:1 复制，`DATABASE_URL` 一直是 `shouwenzeren_newdb` **且内联口令**。此前每次启动都显式 export 覆盖成 fpim_dev，唯独一次从 .env 直接读 → 后端连上原库，冒烟数据写穿了进去。
- 修法三件套：.env DSN 改 fpim_dev 去口令 → config.py 默认值改 fpim_dev + 加 PGPASSWORD 字段 → database.py `_with_password()` 装配时注入口令（所有入口免 export）。

- **教训：同项目两份库时，「默认配置指向哪个库」是最高危项，所有入口的默认值都必须指向开发库。**

## 环境事故：Docker Desktop 会退出 → PG 5432 断 → 前端 network error

- 现象链：Docker Desktop 退出 → PG 容器停 → 后端登录 500 → 前端「network error」
- ⚠️ Docker Desktop 在这台机器上会被关掉（原因未查明，疑似会话进程回收波及）→ **start-dev.sh 已加 PG 自愈**：5432 不通先 `open -a Docker` 再等最多 3 分钟
- 后端有 `pool_pre_ping`，PG 回来后不用重启后端，下一个请求自动重连
- 用户侧自救口诀：打不开/报错就先跑 `./start-dev.sh`
