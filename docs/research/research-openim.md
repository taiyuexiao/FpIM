# OpenIM 调研

- 仓库：https://github.com/openimsdk/open-im-server
- Star/Fork：16,655 / 2,956（2026-09-17 GitHub API 实时）
- 活跃度：在维护，最近 push 2026-09-02；最新 release v3.8.3-patch.16（2026-03-19），服务端停在 v3.8.3 patch 轨道；组织重心转向 AI（仓库描述已改为 "IM Chat OpenClaw"）
- 协议：**服务端 Apache-2.0；客户端 SDK（openim-sdk-core、web/wasm SDK、各端 demo）全部 AGPL-3.0** —— Web 端必须引入 WASM/JS SDK，闭源商用有合规风险，这正是其商业版授权的商业模式

## 技术栈与存储

Go 微服务；存储需 **MongoDB + Redis + Kafka + etcd + MinIO**（docker-compose 核实），不用 PG。Kafka 可降级为 redis/memory（200 人规模单机可省掉 Kafka）。部署约 6~8 个容器。

## 详细功能清单

### 消息能力

- **消息类型**（contentType）：文本(101)、图片(102，原图/大图/缩略图三级)、语音(103)、视频(104)、文件(105)、@提醒(106，含@所有人)、**合并转发(107)**、**名片消息(108，天然支持"个人主页互跳"入口)**、位置(109)、自定义(110，data/description/extension 三段)、引用回复(114)、表情(115)、富文本(117)、群公告/OA 通知
- 离线消息 ✅ / 漫游 ✅ / 多端同步 ✅（服务端全量存储 + 按 seq 拉取）
- **撤回：服务端无时限**（源码核实 revoke.go 无时间窗校验），支持管理员撤回；要"2 分钟可撤"需客户端自限
- **已读回执**：单聊 isRead + 回执 + webhook；**群聊可查看已读人员列表**
- 输入中状态 ✅；本地消息搜索 ✅（WASM 本地索引）+ 服务端 search-msg 全局检索 ✅
- ❌ 无原生 Emoji Reaction（可用 ex/attachedInfo 扩展字段或 modify-message 替代）
- 阅后即焚 ✅（会话级 burnDuration）；消息定时销毁 ✅（msgDestructTime）；流式消息 ✅（为 AI 打字机设计）；文本翻译端点 ✅；批量发送 ✅

### 会话能力

置顶 ✅（可单独拉置顶列表）、免打扰 ✅（会话级 + 用户全局两级）、会话自定义字段 ✅（ex + attachedInfo）、**会话分组 ✅**（类似飞书）、草稿 ✅、未读数全套管理 ✅（总未读/按会话/清零/按 seq 标记已读）、隐藏/删除/清空会话、@未读清除、**增量同步 ✅**（版本号机制，弱网重连友好）

### 群聊

- **统一群组模型**，单群上限 **10 万人**；好友上限 3000
- 角色三级：群主 > 管理员 > 成员（另有全局 APP 管理员）；群主退群须先转让
- 入群方式：邀请直入 / 申请审批 / 开放免审批；入群来源可溯
- 群公告 ✅、全员/指定成员禁言 ✅（带时长）、群成员资料查看开关、群内加好友开关、**新成员可见历史消息可配置**、群内昵称/名片、群成员搜索

### 用户体系

- 三类身份：普通用户、APP 管理员、**系统通知号**（不受权限约束发通知，适合做系统公告/AI 助手账号）
- 资料字段极简（userID/nickname/faceURL/ex），**无部门/职位字段**，业务资料放自己库
- 好友体系完整但**可完全不用**（friendVerify 关闭后纯通讯录模式，默认配置即免好友 ✅）
- 黑名单 ✅；在线状态 ✅（查询/订阅变更/在线终端明细）
- 多端互踢策略可配：全端共存 / 同端互踢（默认）/ 每平台一端 / PC 共存其他互踢
- 账号治理：封禁/注销/强制登出

### REST API 与 Webhook

- REST 约 100+ 端点 9 大模块（auth/user/friend/group/conversation/msg/object/**statistics**/third）——statistics 可直接拿注册数/活跃/建群/群活跃，部分支撑报表
- **Webhook 全集**：消息三个**前置回调可拦截/修改消息（可做内容审核 ✅）**；**afterMsgSaveDB（落库后回调——报表落自家 PG 的最佳挂点）**；撤回/已读/用户上下线/关系链/群组/推送前后/会话创建回调。支持按消息类型过滤、只回调指定用户/群

### 管理后台与客户端

- 开源：ChatServer（用户系统 + 后台管理 API，Apache-2.0）
- ⚠️ 管理后台前端、Web 成品客户端：**闭源（ARR）但免费使用**，docker 镜像分发
- ⚠️ 纯 JS SDK（小程序）：闭源 ARR；WASM/Native SDK：AGPL-3.0

### 推送与存储策略

- 在线走 WebSocket（msggateway :10001）；移动端离线推送：个推/极光/FCM
- **消息默认只保留 365 天**（每日定时清理，可改 retainChatRecords）；文件默认 180 天过期
- 删除：逻辑删除/物理删除/清空会话 API 齐全；**无内置归档**，需 webhook 或直连 Mongo 自建

## 商业版/闭源功能汇总

| 功能 | 状态 |
|---|---|
| 组织通讯录/部门架构 | 💰 商业版 |

## 结论

**不推荐（本项目场景）**——能力最全（消息类型/会话分组/撤回无时限/webhook 体系都是顶配），但客户端 AGPL + 6 组件存储栈对 208 人规模严重过重，组织通讯录还是商业版功能。
