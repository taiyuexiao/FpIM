## 三、开源 IM 项目实现参考速记

> 用途：给「怎么实现」提供组件级/数据模型级先例。项目概况见 `research-openim.md`、`research-wildfirechat.md`。

### OpenIM（openimsdk/open-im-server + openim-sdk-core）

1. **消息类型编码即数据模型**：contentType 数字分段（101 文本 / 102 图片 / 105 文件 / 106 @ / 107 合并转发 / 108 名片 / 114 引用 / 115 表情 / 117 富文本），自定义类型 >1000 —— 自研可直接照搬这套「内置段 + 自定义段」的 msg_type 设计，消息渲染按 type 分发组件。
2. **引用回复结构**：contentType 114 的 quote 消息内嵌「被引用消息摘要 + 引用正文」两段式 payload；对应飞书的引用块展示，落库时冗余一份被引内容快照，避免引用丢失。
3. **未读计数与已读游标**：会话级 unreadCount + 总未读 + 按 seq 批量标记已读（markConversationMessageAsReadBySeq）、@未读单独清除；会话**版本号增量同步**（弱网重连只拉变更），对 FpIM 的 `resyncAll()` 升级有直接参考。
4. **撤回与消息修改**：服务端 revoke 无时限（时限放客户端/管理员配置），管理员撤回、modify-message 可做 reaction/编辑的替代实现；ex + attachedInfo 两段扩展字段承载业务侧自定义（FpIM 的问题挂接可参考此模式）。
5. **搜索双轨**：WASM SDK 本地索引做会话内搜索 + 服务端 search-msg 做全局检索 —— 对应飞书「会话内搜索 / 全局搜索」两层结构。

### WildFireChat（im-server + vue-chat，Vue 3 Web 端）

1. **组件拆分即功能地图**：`ConversationListView/ConversationItemView`（会话列表）→ `ConversationView/MessageItemView`（消息流）→ `MessageInputView`（输入框）→ `message/content/*MessageContentView.vue`（文本/图片/文件/视频/名片/合并转发/贴纸/链接/投票逐一独立组件）—— 消息类型渲染器按 content type 一文件一组件，与飞书消息类型矩阵可一一对应。
2. **消息容器与操作分离**：`NormalIn/OutMessageContentContainerView`（收发气泡容器）+ `MessageMultiSelectActionView`（多选操作条）+ `QuoteMessageView/PreviewQuotedMessageView`（引用）+ `RecallNotificationMessageContentView`（撤回小灰条）+ `MessageReceiptDetailView`（已读回执详情）—— 引用、撤回、回执、多选这四个高频操作都是独立组件，直接可抄结构。
3. **消息列表性能组合**：`vue3-virtual-scroll-list`（虚拟滚动）+ `@imndx/vue-infinite-loading`（上滑加载历史）+ `resize-observer-polyfill` —— Vue 3 长消息流的成熟搭配（Rocket.Chat 用 react-virtuoso/virtua 同思路）。
4. **输入框技术选型**：`tributejs`（@ 提及自动补全）+ `marked` + `anchorme`（链接识别）+ `xss`（输出过滤）+ `@imndx/v-emoji-picker-vue3` + twemoji（emoji 渲染）—— 输入框周边库一次配齐，注意 XSS 过滤是硬要求。
5. **会话类型面板化**：`SingleConversationInfoView / GroupConversationInfoView / SecretConversationInfoView / ChannelConversationInfoView` 按会话类型拆设置面板；另有 `CompositeMessagePage`（合并转发详情页）、`ConversationMessageHistoryPage`（聊天记录页）—— 对应飞书会话设置面板与合并转发详情页的路由拆分。

### Rocket.Chat

1. **消息数据模型字段**（`packages/core-typings/src/IMessage`）：`reactions: {emoji:{usernames}}`（表情回应）、`tmid/tcount/tlm/tshow`（话题/回复聚合）、`replies[]`（回复参与者）、`mentions[]`、`pinned/pinnedAt/pinnedBy`、`starred[]`、`editedAt/editedBy`、`translations`（自动翻译）—— 一张 messages 表覆盖飞书 reaction/引用聚合/置顶/标记/已编辑/翻译，字段命名可直接借鉴。
2. **未读模型在订阅侧**：Subscriptions（user×room）记 `unread/ls/alert/open`，房间消息流推 `stream-notify-room` 增量，`readMessages` 把 ls 推到最新 —— 未读计数与已读游标放在「会话关系」而非「消息」上，与飞书会话级未读/已读语义一致。
3. **消息渲染管线**：`@rocket.chat/message-parser`（自研消息 AST 解析）→ gazzodown（React 渲染器）+ highlight.js（代码块）+ katex + emojibase —— 「解析成 AST 再渲染」的管线让引用/@/链接/代码块统一处理，值得 Vue 侧效仿（解析层可共享）。
4. **虚拟列表**：`react-virtuoso` + `virtua` 并用、overlayscrollbars 自定义滚动条 —— 大消息量会话的渲染基线。
5. **threads（话题回复）交互语义**：回复用 tmid 关联父消息，父消息带 tcount/tlm 聚合计数，`tshow` 控制回复是否回到主流 —— 正是飞书「[N] 条回复 + 回复详情页」的同构实现。

### Turms（turms-im/turms）

1. **收件箱时间线（fan-out 读）**：消息按「会话时间线 + 按用户拉取」组织，push / pull / push-pull 三档同步策略可配 —— 对 FpIM WS 推 + REST 增量拉的混合模型是上位参考。
2. **无状态网关 + 业务服务分层**：turms-gateway（接入/推送/负载均衡）与 turms-service（业务）分离，网关无状态可水平扩、跨数据中心多活 —— 若未来多实例部署，WS 网关与业务写路径分离的边界可照此划。
3. **变更感知与分级存储**：消息分级存储（热/冷）、MongoDB 分片 + 读写分离；服务端配置集群级热更新 —— 消息量上来后的存储治理路径。
4. **内容安全前置**：违禁词过滤用 Aho-Corasick 自动机 + 双数组 Trie，插件事件驱动（antispam/存储/机器人）—— 审核与扩展都走插件点，不侵入核心。

### Tailchat（msgbyte/tailchat）

1. **前端微内核 + 插件系统**：IM 内核极薄，业务能力（机器人、面板、第三方集成）全走插件 —— 飞书「+ 菜单 / 消息快捷操作」挂应用的机制，本质就是插件注册点，自研可预留同款扩展缝。
2. **两级群空间 + 面板**：群空间 → 面板（topic）→ 消息的层次，支持拖拽排序分组 —— 与飞书「会话内标签页 + 话题群」的分区思路同构。
3. **monorepo 类型契约**：`packages/types` 前后端共享类型 —— Vue 3 + FastAPI 项目可用 OpenAPI 生成 TS 类型达成同样效果。
4. **群机器人/通知作为插件接入**：机器人与外部通知不进核心代码 —— 对应 FpIM 群聊 Agent 网关的边界划分（agent 只读推理、写走 backend）。

**粗判小结**：FpIM 已具备飞书消息模块的「骨架」（三栏会话、基础三类消息、撤回、已读游标、草稿、建群拉人、会话内搜索 API），但**消息操作层（引用/表情回应/转发/编辑/多选/标记）与会话管理层（置顶/免打扰/分组/群公告/群权限/会话设置面板）基本空白**——这两层正是飞书 7.x「像不像」的观感来源，建议作为下一期对标重点；搜索层（全局搜索+过滤器）次之。FpIM 独有的问题闭环留痕（问题卡/时间线/首次已读）与「待办」视图继续保留，属于飞书没有的差异化。
