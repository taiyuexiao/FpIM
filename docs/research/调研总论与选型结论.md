# FpIM —— 首问责任平台 IM 化重构调研

> 调研日期：2026-09-17。Star 数、协议、活跃度均经 GitHub API / 官方文档当日实时核实。

## 需求背景

现有"首问责任平台"（Vue3 + Vite + Element Plus / FastAPI 业务后端 :8001 / FastAPI agent-service :8100 / PostgreSQL + pgvector，真实数据约 208 人、32 部门）的核心痛点：**找到人之后，沟通靠邮件往来，低效且问题处理过程无法留存**。

领导要求重构为 **PC 端优先的 IM 即时通讯软件**（对标飞书）：

- 个人中心、个人标签、个人自画像等合并为「个人主页」（参考飞书个人名片页）
- 保留现有"左侧会话记录 + 右侧提问输入框"的 ChatGPT 式 UI 作为**搜人入口**；搜到人后直接跳入聊天框对话
- 内置通讯录（已有组织树），**免加好友直接单聊**；个人主页可点击跳转到对方主页，含上级标注
- 承载人才选拔功能：统计谁提问多、提问价值、哪个部门被提问最多、解决成果，生成报告发领导
- 设计理念：管理视角解决问题——ToB 产品通过"制造麻烦"（留痕、催办、状态曝光）倒逼被询问者解决提问者的问题；画像/排名与人力资源系统联动，纳入人才选拔机制

## 候选方案总结论

| 方案 | 结论 | 一句话理由 |
|---|---|---|
| **JuggleIM 内核 + Vue3 自研 UI** | 推荐（集成派首选） | Apache-2.0 活跃维护，"IM 内核 + 自有业务后端"模型与现有系统严丝合缝，免好友单聊天然支持 |
| **FastAPI 全自研 WebSocket IM** | 推荐（自研派首选） | 208 人单聊规模技术完全可行，消息直接落自己的 PG，报表与 AI 搜人链路零对接成本；代价 4~8 人周 |
| Zulip | 可选 | Apache-2.0 无阉割、PG 存储、免费 SSO，但部署最重、无嵌入模式、话题模型有学习成本 |
| Rocket.Chat | 可选 | 最像飞书、iframe 嵌入成熟，但已读回执/统计是付费功能且免费范围逐年收缩，MongoDB 与现有栈割裂 |
| WuKongIM / 唐僧叨叨 | 可选（备选内核） | 部署最简，但 v3 仍是 beta，持久化格式可能变更 |
| 野火 IM | 不推荐 | CC BY-ND 禁止演绎；Web/PC 必须付费（约 3.9 万起）；Java/MySQL 栈不匹配 |
| OpenIM | 不推荐 | 服务端 Apache 但客户端 SDK 是 AGPL-3.0；Mongo+Kafka+etcd 6+ 组件对 208 人严重过重 |
| Mattermost | 不推荐 | v11 免费版 250 人上限 + 无 SSO + 无已读回执；自编译落入 AGPLv3 |
| Tailchat | 不推荐 | React 前端无法融入 Vue3，Discord 式群组模型不符"通讯录单聊" |
| LumenIM | 不推荐（可参考） | 无开源协议 + 已停更，但可作自研 UI/表结构参考样本 |
