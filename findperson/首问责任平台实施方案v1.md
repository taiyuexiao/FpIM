4.1 意图识别

意图枚举（4 种 + 兜底）：

意图标识
含义
触发动作

找人咨询

修改个人资料 / 为他人画像

识别架构：规则加速 + 大模型判断 两层串联

- 第一层规则引擎：特征明显输入直接路由，响应快、成本低
- 第二层大模型：规则未命中或置信度低时调 LLM
- 规则命中且置信度高 → 直接返回，不调 LLM
- 大模型不可用 → 降级到纯规则匹配
主动追问：意图置信度低、关键槽位缺失、检索结果为空时触发。前端展示为追问卡片。

兜底机制：多路召回均无结果 → 诚实告知 + 引导补充关键词。

4.2 推荐系统

采用 多路召回 + 可配置加权精排 架构。

三路召回：

召回路
方法
特点
规则召回

快、可解释、可控，兜底和冷启动

精排因子（可配置权重）：规则匹配分、向量相似度、内容关联度、负责领域重合度、人员资料完整度、资料新鲜度、与提问人的部门接近程度、历史推荐反馈分数（含时间衰减）。

推荐理由：Agent 为每位推荐人组织理由（负责领域命中、个人资料相关描述、关联文章），拼 prompt 调 LLM 生成。

4.3 记忆

- 短期记忆：结构化摘要 + 可选原文，Markdown 格式拼接进 prompt
- 每轮追加：轮次编号、用户原文、摘要、意图、置信度、槽位、执行结果、关联实体、系统回复
- 超 20 轮后压缩最旧轮次
- 持久化到 PostgreSQL `agent_sessions` 表
- 预留脱敏接口
4.4 反馈回流

- 推荐卡片提供赞/踩入口；不点赞记为中立
- 点踩弹出详细反馈弹窗（信息过时/不负责这块/联系方式错了/推荐对但理由没用/应推荐别人/自由文本）
- 反馈连同会话、轮次、推荐对象、用户身份保存到 feedback 表
- 运营层：后台看板展示准确率、赞踩比等
- 算法层：信息过时 → 通知更新资料；推荐不准 → LLM 给标签/权重打补丁
- 准确率持续低于阈值 → 自动告警

五、RAG 知识库层

5.1 职责

1. 将知识文档（内容、人员信息）通过切片、向量化建立索引
2. 接收查询文本，返回最相关的文档片段
5.2 服务架构

┌──────────────────────────────────────────────────────┐
│  对外接口层                                           │
│  retrieve  ← Agent 层调                              │
│  search    ← 后端接口层调（只查本人发布）               │
│  ingest    ← 后端接口层调（发布/编辑内容时）            │
│  delete    ← 后端接口层调（删除内容时）                │
│  update_payload ← 后端接口层调（置顶时）               │
│  health    ← 运维监控                                 │
├──────────────────────────────────────────────────────┤
│  核心处理层                                           │
│  入库：ingest → 分块 → jieba 分词                     │
│        → 通义千问 embedding → 写 rag_chunks            │
│  检索：retrieve → embedding → pgvector 向量查          │
│        + jieba 分词 → tsvector 全文查                  │
│        → RRF 融合 → 返回 top k                        │
├──────────────────────────────────────────────────────┤
│  存储：PostgreSQL（与后端共用）→ rag_chunks             │
└──────────────────────────────────────────────────────┘

5.3 内容切片（content 类型）

- 按段落（连续两个换行）切分
- 段落 > 500 字 → 按句子边界二次切分，保留 50 字 overlap
- 段落 < 30 字 → 合并到前一段落
- 每个 chunk 做 jieba 分词 + 通义千问 embedding → 写入 rag_chunks
5.4 人员索引（person 类型）

不切片，整条打包为 1 个 chunk。拼接顺序（自画像和领域重复一次以增加权重）：负责领域 ×2 + 自画像 + 角色 + 姓名 + 部门 + 全部他画像（时间倒序）。超出 8000 token 时从最旧的他画像开始逐条移除。

5.5 检索流程（retrieve）

1. 向量检索：通义千问 embedding → pgvector `<=>` 余弦距离 → top 6
2. 全文检索：jieba 分词 → tsvector + ts_rank → top 6
3. RRF 融合：两路按排名倒数加权合并
4. 返回 top_k 个 chunks
容错：通义千问 API 不可用 → 自动降级为仅全文检索。

5.6 内容搜索（search）

后端调用，只返回当前用户本人发布的内容：调 search → 按 doc_id 去重 → 按 owner_id 过滤 → pinned 降序 + score 降序 → 分页返回。只返回 content 类型。

5.7 rag_chunks 表结构

RAG 启动时自动创建（CREATE TABLE IF NOT EXISTS），DBA 需先安装 pgvector 并授予 CREATE 权限。

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS rag_chunks (
    id          TEXT PRIMARY KEY,
    doc_type    TEXT NOT NULL,          -- 'content' | 'person'
    doc_id      TEXT NOT NULL,
    chunk_index INT DEFAULT 0,
    content     TEXT NOT NULL,
    fts_text    TEXT,
    embedding   vector(1536),
    metadata    JSONB DEFAULT '{}',
    created_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_rag_chunks_vector ON rag_chunks
