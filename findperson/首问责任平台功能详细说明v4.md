# 首问责任平台功能详细说明 v4

本文档依据《首问责任平台功能说明及前端展示》、当前 Vue 前端页面及交互整理，用于统一产品、前端、后端和 Agent 的建设边界与验收口径。本文描述的是目标功能规格，并同步记录截至 2026 年 7 月 29 日的前端实现状态；当前演示前端仍使用模拟数据和本地存储，真实认证、业务数据、审核流与 Agent 服务须由后端落地。

一、产品定位与范围

首问责任平台面向组织内部“找人难、协同慢、责任不清”的问题，提供统一咨询入口、责任人定位、人员能力沉淀和知识内容治理能力。用户不必先知道部门或具体联系人，可通过自然语言提出问题，由系统给出可解释的首问责任人、协助人员或明确的转办建议。

平台的核心闭环为：用户提问或主动查找人员，查看人员职责与可联系信息，完成协同；人员持续维护个人画像并发布经验内容；同事补充协作画像；管理员维护组织和审核内容；沉淀的信息反向提升后续推荐质量。

平台包含智能问答、名片库、人员主页、个人中心、内容发布与详情、他人画像、操作手册、后台管理八类业务页面。平台不建设独立内容检索门户；已发布内容仅在人员主页、个人中心、内容详情和问答关联结果中展示，并作为人员推荐的辅助依据。

二、用户、角色与权限

普通成员：可登录、发起问答、查看名片库和公开人员主页、查看已发布内容、维护本人联系方式/负责领域/自画像、为他人补充画像、创建和维护本人内容。普通成员不能维护他人资料、组织结构、成员账号或审核他人内容。

部门负责人：具有普通成员全部能力；可维护本人所在部门及其下级部门的部门职责。部门负责人身份由组织管理中的部门负责人关系确定，不以岗位名称推断。

管理员：具有普通成员全部能力，并可进入后台管理，维护成员、部门、部门负责人和系统角色，审核内容，查看全局运营数据。管理员的前端入口须仅对管理员显示，接口层仍必须二次校验权限。

内容发布人：内容所有者可保存草稿、提交审核、编辑自己的内容、删除自己的内容和置顶自己的已发布内容。管理员审核前，内容不得在公开人员主页展示，也不得进入推荐依据。非所有者和非管理员不能修改或删除该内容。

三、总体布局与通用规则

登录后页面采用固定左侧导航、顶部用户区和右侧工作区布局。左侧主导航包含“智能问答”“名片库”，管理员额外可见“后台管理”；“个人中心”通过右上角用户菜单进入。主导航仅负责页面切换，不应新建会话、清除搜索条件或触发业务提交。

右上角用户区展示当前用户头像和姓名，菜单包含个人中心、修改密码、操作手册和退出登录。修改密码采用弹窗，包含原密码、新密码、确认新密码；需校验原密码、新密码规则和两次输入一致性。退出登录应清除登录态并跳转登录页。

未登录用户访问任一业务路由时跳转登录页；已登录用户访问登录页时跳转智能问答；无管理员权限访问后台管理时跳转智能问答。前端须先恢复并校验登录态，再加载人员、内容、评价和会话等业务数据；不得在浏览器持久化用户密码。人员主页、内容详情、发布页和他人画像页均有返回入口，返回目标使用完整内部来源路由，无来源时回到其默认上级页面。

所有会改变业务数据的操作均需给出明确结果状态。提交失败时保留用户当前输入并显示可理解的失败原因；删除、审核通过、审核驳回等不可逆或影响较大的操作应进行二次确认。资料编辑、他人画像和内容发布存在未保存修改时，离开页面应提示用户确认；登录失效或主动退出不应被未保存提示阻断。前端按钮隐藏不能替代服务端授权校验。

四、智能问答

智能问答是登录后的默认首页，由历史对话栏、主对话区和右侧详情栏组成，三个区域独立滚动。历史栏固定显示，右侧详情栏默认隐藏；主对话区右上角提供详情栏开关。

历史对话：展示当前用户全部会话，单条显示标题、摘要或更新时间及当前选中状态。支持新对话、关键词搜索、重命名和删除。搜索范围包括会话标题、用户问题、回答摘要和识别意图。点击主导航“智能问答”只回到当前工作台；点击“新对话”才创建会话。若已有空白会话，应复用空白会话，避免产生连续空记录；删除最后一条会话后，系统保留一个可用空白会话。

主对话区：空白会话显示简洁的“开始对话”和输入框。输入框支持多行输入，Enter 发送、Shift + Enter 换行；空白内容不得发送。发送后立即生成用户消息、流式或阶段性的助手回答和对应业务卡片，输入框清空。会话消息与卡片均按会话隔离，切换历史会话后恢复其上下文。

意图识别：系统至少识别“找责任人”“维护本人资料”“发布内容”“为他人画像”四类可执行意图；对无法确认的找人问题可追问范围、系统、事项、部门或期望处理结果。除此之外，系统可以回答已授权的知识问题，但不得把无依据的推断表述为正式责任结论。

推荐结果：找人类问题返回至多三位候选人，依次标记为“首推”“可协助”“相关人员”。每张卡片展示姓名、部门路径、岗位、领域标签、联系方式摘要、推荐理由及查看主页入口。推荐理由必须指出命中的职责、领域、画像、正式责任、已发布内容或组织关系，不可只显示“匹配度高”。

反馈：回答和推荐人员卡片提供“有帮助 / 没帮助”反馈。同一用户对同一对象同一时刻仅保留一种反馈，再次点击可取消。推荐反馈应关联会话、消息和追踪标识，供后续评估推荐效果；轻量内容反馈不可替代 Agent 推荐反馈。

五、问答业务卡片与右侧详情栏

资料维护卡：识别到用户拟修改联系方式、负责领域或自画像时，展示变更项和“确认更新主页”“手动编辑”。确认后仅更新当前用户可维护字段，并同步个人中心、名片库、人员主页和推荐索引；字段不完整时引导用户至个人中心补充。手动编辑通过草稿标识进入个人中心编辑态并回填已识别字段。完成后卡片变为已完成状态，不得重复提交。

他人画像卡：展示评价对象、日期和事项草稿，提供“确认保存评价”“查看评价对象”或“继续修改”。继续修改通过草稿标识进入他人画像页并回填对象、日期和事项。保存前校验评价对象非本人、日期和事项非空、事项不超过 20 个字符；保存后写入目标人员的他画像及当前用户的“我添加的事项”列表。相同评价人、评价对象和事项的重复提交按更新处理，避免重复记录。

内容发布卡：展示标题、关联领域、摘要与正文草稿，提供“确认发布”和“手动补充”。确认发布按普通发布流程生成内容并进入待审核状态，成功提示不得表述为已经公开发布；手动补充通过草稿标识跳转发布页并回填标题、领域、摘要和正文。审核通过前不得对外公开或参与推荐。

右侧详情栏：点击问答中的人员、内容或待确认卡片后展开。人员详情显示完整部门路径、岗位、联系方式、负责领域、自画像、他画像摘要和已发布内容，并可进入人员主页；内容详情显示标题、发布人、领域、摘要和正文，并可进入内容详情页；操作详情显示待提交字段与确认动作。详情栏关闭前保持当前对象，继续追问不得自动清空。

六、名片库与人员主页

名片库展示当前用户可见的全部人员名片。顶部提供关键词搜索和部门树筛选；关键词应匹配姓名、部门路径、岗位、领域标签、自画像、部门职责等信息。部门树支持选择任一节点并包含其下级部门成员，重置后恢复全量列表。关键词与部门条件须同时生效。

名片以卡片列表或网格展示，包含姓名、完整部门路径、岗位、领域标签、自画像摘要和联系方式。点击卡片进入人员主页；无匹配记录时显示空状态。名片库不提供修改他人资料或直接发布内容的入口。

人员主页展示公开职责信息，包括姓名、部门路径、岗位、联系方式、上级信息、负责领域、自画像、他画像、部门职责和已发布内容。上级信息可点击进入上级人员主页；没有有效上级时展示“暂未设置”。部门职责展示人员所属部门的职责说明。

他画像由有效的他人评价按事项聚合，展示事项名称、不同评价人数和最近评价日期；相同事项只显示一个聚合项。显示排序先按评价人数降序，再按最近评价日期降序。可使用气泡图或等效可视化，大小反映评价人数；无有效记录时显示空状态。

人员主页仅展示已发布内容。内容卡片展示标题、发布人、发布日期、关联领域、摘要和置顶标识，点击进入内容详情。待审核、草稿和已驳回内容不得从公开人员主页进入。

七、个人中心与部门职责

个人中心默认展示当前用户的资料摘要、上级信息、负责领域、自画像、他画像、部门职责和“我的发布”。顶部提供“编辑”“为他人画像”“发布”三个动作。个人中心不是管理员成员资料编辑入口，姓名、部门、岗位和系统角色由管理员统一维护。

编辑个人资料：用户仅可编辑联系方式、负责领域和自画像。负责领域支持多个标签；保存后立即刷新当前用户名片、人员主页和问答匹配可用信息。取消编辑不保存任何变更。

部门职责：普通成员只读查看本人所在部门职责。部门负责人可查看并编辑本人负责部门及全部下级部门职责，可按部门筛选并逐条保存。部门负责人范围由部门树的负责人关系计算；用户卸任负责人后立即失去对应编辑权限。

我的发布：展示当前用户的草稿、待审核、已发布和已驳回内容，支持关键词筛选。卡片应显示当前状态及审核意见。内容所有者通过明确的“编辑”“删除”“置顶/取消置顶”按钮管理内容；点击卡片仅进入详情，不应直接进入编辑。置顶仅允许对本人已发布内容生效。

八、他人画像

“为他人画像”页面用于记录协作事项。表单包括同事、日期和事项。同事从可见人员中选择，且必须排除当前用户本人；事项支持按目标人员的负责领域和既有画像事项搜索选择，也可选“其他”并填写不超过 20 个字符的自定义事项。

提交时，同事、日期、事项均为必填；选择“其他”时必须填写自定义事项。保存成功后，记录写入目标人员的他画像，并显示在“我添加的事项”中。列表按记录展示对象、日期、事项，支持“继续补充”和“删除”；继续补充需回填原始字段并更新原记录。

评价记录应至少保存评价人、被评价人、事项标签、评价日期、创建时间、更新时间和状态。删除采用逻辑删除或保留审计记录，已删除评价不得参与人员主页聚合或推荐。

九、内容发布、审核与详情

内容发布页用于新增、编辑本人内容或承接问答草稿。表单包含标题、关联领域、发布人、内容摘要和发布内容；发布人默认为当前用户且不可改为他人。标题、摘要和正文为提交审核必填项；关联领域用于后续人员推荐与内容关联。

内容状态包括草稿、待审核、已发布和已驳回。保存草稿仅本人可见；提交审核后进入待审核；管理员通过后变更为已发布；管理员驳回后变更为已驳回并记录驳回原因。已发布内容再次编辑并提交时，应产生待审核版本；在新版本通过前，可继续对外展示最近的已发布版本，避免公开内容突然消失。

内容详情展示标题、发布人、发布日期、关联领域、摘要、正文、发布状态和可见的审核信息。内容详情不直接承担编辑和删除操作；内容所有者通过个人中心“我的发布”进入编辑。非公开状态的当前版本仅对所有者和管理员可见；若内容存在已发布快照且新版本处于待审核或已驳回状态，其他用户通过同一内容地址继续查看最近已发布快照。

十、后台管理

后台管理仅管理员可访问，包含数据看板、成员管理和内容审核三个页签。

数据看板：展示参与人员数量、已发布内容数、待审核内容数和本周推荐量。参与人员数量按启用成员统计；已发布内容只统计状态为已发布的内容；本周推荐量按自然周内有效推荐记录汇总。页面展示本周推荐热度排行和周日活趋势。本周/上周切换仅切换统计周期，不应修改历史数据。

成员管理：管理员可新增和编辑成员，维护姓名、所属部门、职务、是否担任部门负责人、系统角色和账号状态。部门选择使用组织树；新增部门时需指定上级部门、部门名称和部门职责。部门负责人变更后，应同步影响上级展示、部门职责编辑权限和组织筛选结果。停用成员后不得登录，且不再参与新的推荐；其历史内容、评价和审计记录按数据保留策略处理。

内容审核：管理员可查看待审核、已发布、已驳回内容。审核通过后记录审核人和审核时间；驳回必须填写原因，并将原因反馈给内容所有者。审核结果需写入审核轨迹，轨迹至少记录内容版本、操作人、操作时间、操作结果和驳回原因。

十一、推荐、知识与责任判定规则

人员推荐按证据优先级排序：正式责任关系优先，其次为本人维护的负责领域和岗位职责，再次为自画像、已审核发布内容、他人画像与组织协作关系。高优先级正式责任不得被文章热度或历史点击量反超；他人画像只能作为能力佐证，不能单独认定正式责任人。

系统应从问题中抽取事项、领域、系统、部门、人员和关键词，并在授权范围内匹配人员与责任资料。若存在正式责任关系，回答应说明首问受理部门、责任人或岗位、协助部门、转办条件、办理时限和升级路径；若不存在足够依据，应明确说明“暂未定位到正式责任人”，给出补充信息或转人工建议，不得编造联系人。

问答回答应区分“已检索事实”和“系统建议”。涉及制度、流程、责任关系、知识内容的结论应保留来源标识、版本或可追溯链接。资料维护、发布内容、提交评价等写操作必须经用户确认，并通过受权限保护的业务接口执行；Agent 或知识检索服务不得直接写业务事实数据。

十二、数据对象与状态要求

人员：用户标识、姓名、所属部门、完整部门路径、岗位、联系方式、系统角色、账号状态、负责领域、自画像、推荐次数、上级关系、更新时间。

部门：部门标识、部门名称、上级部门标识、完整路径、负责人标识、部门职责、状态、更新时间。组织结构应支持多级扩展，页面筛选和负责人管理不得限制为固定三级。

内容：内容标识、发布人、标题、关联领域、摘要、正文、状态、当前版本、已发布快照、置顶状态、提交时间、发布时间、更新时间、审核轨迹。内容不设置独立“内容类型”字段。

会话与消息：会话标识、用户标识、标题、创建/更新时间、摘要；消息标识、角色、正文、运行标识、来源引用、推荐卡片和确认卡片。会话与消息必须按用户隔离。

评价：评价标识、评价人、被评价人、事项标签、评价日期、状态和审计字段。兼容历史数据时可读取旧文本字段，但新写入统一使用事项标签字段。

推荐与反馈：推荐记录保存问题摘要、候选人员、排序证据、会话/消息/运行标识、创建时间；反馈保存反馈主体、反馈对象、反馈值和时间。推荐、内容和人员数据的统计口径必须可追溯到对应记录。

十三、接口与非功能要求

业务接口至少覆盖认证、当前用户、人员与部门、内容、评价、会话、问答、反馈和后台统计。所有接口以当前登录身份执行授权，敏感数据仅返回调用方有权查看的字段。对成员停用、角色变更、部门负责人变更、审核、删除等管理操作必须记录审计日志。

问答接口应支持消息流式返回，事件至少包含运行开始、文本增量、文本完成、推荐卡片、确认卡片、状态变更、运行失败和运行结束。每个运行事件携带会话标识、运行标识和消息标识，客户端在切换会话或刷新后不得将事件串入其他会话。

平台需保证移动端和桌面端的基础可用性；长文本、长部门路径和大量标签不得挤压关键操作。搜索、筛选、切换会话、打开详情等交互应保持当前未提交编辑内容不丢失。前端路由应按页面拆分加载，组件库按需注册，避免全部业务页面进入首屏入口包。真实服务需处理接口失败、超时和权限变更，提供明确错误提示而非静默失败。

十四、核心验收场景

1. 普通用户登录后默认进入智能问答，可创建、搜索、重命名、删除会话；删除全部历史后仍可继续提问。
2. 用户提出责任人问题后，可看到带可解释理由的推荐卡片，点击卡片打开详情栏，并可进入人员主页和联系负责人。
3. 用户通过问答修改本人资料、发布内容或评价他人时，系统先生成确认卡；确认后只更新被授权的数据并展示完成状态。
4. 名片库可按关键词和任意部门节点及其下级筛选，人员主页可查看上级、部门职责、画像和已发布内容。
5. 部门负责人可编辑本人负责部门及下级部门职责，普通成员和其他部门负责人无权编辑不在范围内的部门。
6. 普通用户提交内容后进入待审核，公开主页不可见；管理员审核通过后可见并参与推荐，驳回后发布人可见原因并修改重提。
7. 管理员可新增/编辑成员、维护负责人和账号状态；停用成员不能再次登录或参与新的推荐。
8. 普通用户不可进入后台管理，也不能通过接口修改他人资料、他人内容、组织信息或审核状态。

十五、实施边界

当前前端演示可用于流程验证，但本地模拟数据、浏览器存储、规则匹配和前端权限控制均不能作为生产实现。生产版本应接入统一认证、持久化业务数据库、服务端权限校验、审计日志、真实审核工作流与可追溯的 Agent/知识服务。

后续新增功能，如工单办理、责任事项台账、跨部门转办、催办升级、内容分级可见、数据导出等，需另行评审数据模型、权限、流程时限和审计规则，不应在本说明范围内隐式实现。

十六、当前前端实现状态
