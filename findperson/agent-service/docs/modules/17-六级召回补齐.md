# 模块 17:六级召回补齐(pg_trgm + Concept Vector)

## 背景

对应 V1.2 §7.3(RawTag → Concept Candidate Recall 的完整五级)与阶段 2「Concept 动态治理能力」。模块 13 只实现了前三级确定性召回(Exact/Alias/Historical),本模块补齐第四级 pg_trgm Fuzzy 与第五级 Concept Vector Recall。文档红线:**向量只用于候选召回,不直接形成最终映射**;两个向量空间(RAG 1536/Concept 1024)独立(§10.8)。

## 任务

- 输入:任意表达文本(查询侧/员工侧)
- 输出:五级候选召回 + Concept 向量回填(69 个种子概念,1024 维)
- 验收:trgm 召回近似概念;向量召回相关概念;trgm/vector 候选**不自动 resolved**;前三级短路;max_level=3 向后兼容

## 实现方式

- `app/agent/concept_linker.py` **ConceptCandidateRecall 扩展**:
  - `recall(text, max_level=5)`:前三级命中即短路返回;否则继续——
  - **第四级 pg_trgm**:`canonical_name % text` 模糊匹配,`similarity()` 排序取 Top5,**分数封顶 0.89**(压在自动确认阈值 0.9 之下)
  - **第五级 Concept Vector**:`get_concept_embedding()`(1024 维)embed 查询 → 与 agent.concepts.embedding 逐条余弦(概念库百级,全量内存计算符合 §0.1 规模前提),**分数封顶 0.85**,min_score=0.25,Top5
  - **确认规则收紧**:`AUTO_RESOLVE_SOURCES = (exact, alias, historical)` —— 只有确定性三级可自动 resolved,trgm/vector 候选保留给第六级(模块 18)
  - `max_level=3` 保持阶段 1 行为(向后兼容)
- `scripts/backfill_concept_embeddings.py`:为 69 个 seed/active 概念计算 Mock Embedding(canonical_name+description),写入 embedding + embedding_model(mock-concept-embedding-v1,模型版本化 §23);幂等可重跑
- 测试 `tests/test_concept_recall_levels.py`(5 用例):trgm 召回「数据治理工作」→数据治理、向量召回相关数据领域概念、前三级短路、trgm/vector 不自动 resolved、max_level=3 兼容,全部通过(累计 86 passed)

## 遇到的问题报错及解决方法

1. **asyncpg 把 vector 列读成字符串**:`list(r["embedding"])` 实际是逐字符迭代(1024 维向量变成 2724 个字符),cosine_similarity 报「向量维度不一致 (1024,) vs (2724,)」。
   解决:_vector_recall 里对 str 类型做 `strip("[]").split(",")` 解析为 float 列表。
2. **向量分压过 trgm 分导致断言失败**:Mock 向量对高重叠文本余弦可达 0.9+(封顶 0.85),而 pg_trgm 对「数据治理工作/数据治理」相似度仅 ~0.5(×0.95≈0.47),vector 排到 trgm 前面,原断言「top 必须是 pg_trgm」过严。
   解决:测试改为断言「包含 pg_trgm 召回且分数 <0.9」,不强制排序——两级召回是候选集关系,排序本来就该交给第六级消歧。
