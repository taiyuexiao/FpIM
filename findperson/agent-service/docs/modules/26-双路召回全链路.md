# 模块 26:RAG 证据适配 + Find Person 双路召回

## 背景

对应 V1.2 §10.11(Find Person RAG Evidence Adapter:知识证据→人员证据;**RAG 相似度不得直接等价为责任人分数**;文章作者不得标为正式负责人)、§8.1(diagnostic/expert_finding 双路:StructuredRetriever 与 KnowledgeRAG 并联)、§9.4(正式责任正式路径 = MCP get_responsibility)、§10.10(knowledge_qa 全链路)。至此主链双路真正贯通,模块 14 的 Mock 责任适配器退为降级备胎。

## 任务

- 输入:RagHit[](带 chunk metadata)、diagnostic/expert_finding 查询、knowledge_qa 查询
- 输出:RagEvidenceAdapter、KnowledgeRetrievalNode(并联)、KnowledgeQANode、MCP 正式责任路径
- 验收:双路证据都进融合;contact_lookup 零 RAG;MCP 失败降级有标记;knowledge_qa 有引用、无证据不编造

## 实现方式

- `app/rag/evidence_adapter.py` **RagEvidenceAdapter**(§10.11):
  - responsibilities → 责任人 formal_assignment,**confidence=1.0 与相似度无关**
  - contents → 作者 article_expertise,confidence 上限 0.6(相似度只作弱参考)
  - people → inferred_from_profile / inferred_from_review(评价段),上限 0.55
  - 部门等无人关联文档跳过
  - 配套修复:RagHit 契约补 `metadata` 字段(chunk 元数据携带 owner_person_id/author_person_id),retriever 填充
- `app/agent/nodes/knowledge_retrieval.py`:
  - **KnowledgeRetrievalNode**:仅 diagnostic/expert_finding 执行(§8.1);MCP search_knowledge → rag_documents + adapter → rag_person_evidence;MCP 失败 → degraded_sources 标记继续(路径 A 仍可用,§21 基线)
  - **KnowledgeQANode**:knowledge_qa → MCP search_knowledge → rag_documents
- `chain.py` 主链升级:diagnostic/expert 时 `add_parallel([StructuredRetrievalNode, KnowledgeRetrievalNode], label="RetrievalCoordinator")`(§3.1);其余 find_person 仅结构化路;KnowledgeQANode 挂 knowledge_qa 条件
- `structured_retrieval.py`:正式责任改走 **MCP get_responsibility 正式路径**,MCP 失败才降级 Mock 直读(显式 degraded 标记,§18)
- `answer_builder.py`:knowledge_qa 占位分支替换为真实实现(有证据→事实+引用;无证据→诚实空答)
- **关键修复**:`apply_update` 的 RetrievalState 合并语义从「整体替换」改为「列表字段去重追加」——并行节点各自 model_copy 后整体回写会互相覆盖(后写完的抹掉先写的证据)
- 测试 `tests/test_dual_path.py` 等(7 新用例):适配器三类转换+红线、diagnostic 双路并联(stub 意图/结构化器,确定性)、contact_lookup 零 RAG、MCP 正式责任路径无降级标记、MCP 失败降级 Mock、knowledge_qa 带引用/诚实空答,全部通过(累计 130 passed)

## 遇到的问题报错及解决方法

1. **并行节点证据互相覆盖(隐蔽的状态合并 bug)**:diagnostic 全链路中 structured_candidates 神秘丢失——两个并行节点各自 `model_copy(deep=True)` 得到同一 base 副本,`apply_update` 整体替换 state.retrieval,后完成的 KnowledgeRetrievalNode 把 StructuredRetrievalNode 写的 structured_candidates 抹掉。
   解决:`apply_update` 对 RetrievalState 五个列表字段改为「JSON 去重追加」合并语义;串行节点因 model_copy 已含旧值,语义等价无回归(130 全过)。
2. **全链路测试依赖真实 LLM 输出不稳定**:LLM 把「数据治理平台」抽成系统词,精确/别名/历史三级对不上概念,结构化召回为空。
   解决:该测试改为经 ServiceRegistry 注入 stub intent_service/query_structurer(确定性),LLM 相关泛化能力留给模块 28 评测集验证。
