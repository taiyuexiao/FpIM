# 模块 29:稳定性(降级链 / 超时 / 并发压测)

## 背景

对应 V1.2 §19 阶段 8(稳定性:Timeout、Circuit Breaker、LLM Fallback、MCP Fallback、Embedding Fallback、RAG Fallback、Cache、Concurrency、Pressure Test)和 §21 验收基线(简单找人 P95<2.5s、复杂诊断 P95<6s、**MCP 不可用时路径 A 可降级 100%**、**Embedding 不可用时关键词检索可降级 100%**)。大部分降级能力在前序模块已内建,本模块补齐缺口并做整体压测验证。

## 任务

- 输出:Embedding 故障 RAG 降级、全链超时、并发压测报告
- 验收:Embedding 挂→关键词单路可用;全链 30s 上限;并发下成功率与延迟达标

## 实现方式

- **Embedding Fallback(新补)**:`HybridRetriever` 向量路整体 try/except——Embedding 故障时降级为 FTS/pg_trgm 关键词单路(日志告警),检索不中断(§21 基线 100%)
- **全链 Timeout(新补)**:`/agent/chat` 用 `asyncio.wait_for(30s)` 包住 `orchestrator.run()`,超时走 SSE `run_error(TIMEOUT)` 事件(建流后错误协议,§5.1)
- **已内建(前序模块)**:
  - LLM Fallback:IntentNode → RuleFallbackRouter(模块 11);QueryStructurer → 词典匹配降级(模块 12)
  - MCP Fallback:CircuitBreaker 3 次断开/30s 半开(模块 25);MCP 挂 → 责任查询降级 Mock 直读、知识路降级路径 A(模块 26)
  - RAG Fallback:索引未建/失败 → AgentError(degraded)(模块 23/24)
  - Cache:概念词典/query→concept/MCP 短缓存(模块 07/13)
- **并发压测** `scripts/pressure_test.py`:并发 8 × 24 请求(简单/复杂混合)
  - **真实 DeepSeek**:24/24 成功(100%),简单 P95=8.4s、复杂 P95=11s——**超基线,瓶颈是 LLM API 时延**(每请求 2 次串行 LLM 调用,意图+结构化;§0.1 已预判「并发瓶颈在 LLM 调用,不在数据库」)
  - **Mock LLM(纯框架路径)**:24/24 成功,总耗时 0.4s,简单 P95=326ms、复杂 P95=298ms——**远优于基线**,证明框架/DB/检索路径性能达标,延迟完全由外部 LLM 决定(生产换行内 LLM 服务后复测)
- 测试 `tests/test_stability.py`:BrokenEmbedding 降级单路可用、正常双路不受影响,全部通过(累计 139 passed)

## 遇到的问题报错及解决方法

1. **pg_trgm 对中文短词系统性失效(隐性 bug,被向量路掩盖多时)**:`content % '数据治理'` 的 `%` 运算符默认阈值 0.3,而 CJK 短串 trigram 极少,真实最大 similarity 仅 0.25——FTS 路实际一直返回空,之前 test_fts_recall 是被向量路「带过」的。降级测试(向量路掐断)才暴露。
   排查:写探针脚本直接测 similarity 值分布确认。
   解决:FTS 路改为「ILIKE 子串命中(中文查询词多为内容子串)+ similarity>0.15 低阈值 trgm」双通道,similarity 仅用于排序。修复后降级单路有真实命中。
2. **psql 中文查询编码坑**:PowerShell 直接传中文 SQL 报「无效的 UTF8 编码字节顺序」,PGCLIENTENCODING 也无效。
   解决:SQL 写入 UTF-8 临时文件用 `psql -f` 执行。
