# 模块 01:项目骨架与配置

## 背景

对应 V1.2 文档 §19 阶段 0「公共契约冻结」的前置工作。任何模块开发前,需要先有可运行的工程骨架、统一的配置入口和依赖基线。V1.2 §18 共同责任要求「密钥、模型地址和数据库密码不得写死」,因此配置必须集中在 `.env` + 统一 Settings 入口。

## 任务

- 输入:无(从零建工程)
- 输出:可启动的 FastAPI 工程;`/health` 返回 200;依赖一次安装成功
- 验收:`uvicorn app.main:app` 启动,`GET /health` 返回 `{"status": "ok"}`

## 实现方式

- 目录结构按开发计划建立:`app/{contracts,core,agent,retrieval,okf,rag,mcp_knowledge,eval}`、`scripts/ddl`、`tests`、`docs/modules`、`data`、`knowledge-okf`
- `app/config.py`:pydantic-settings `Settings`,从 `.env` 读取 LLM(DeepSeek)、Embedding(Mock 双维度)、PostgreSQL(新库 shouwenzeren_v2 + 旧库 shouwenzeren 只读迁移源)、服务端口、OKF 仓库目录、MCP 开关;`get_settings()` 用 `lru_cache` 做单例
- `.env`:复用旧项目的 DeepSeek key 和 PG 凭据;`LLM_USE_MOCK=0`、`EMBEDDING_USE_MOCK=1`(Embedding 模型未定,按 V1.2 §23 先用 Mock)
- `app/main.py`:FastAPI 入口,当前仅挂 `/health`,返回服务状态与 mock 开关
- `requirements.txt`:fastapi / uvicorn / sse-starlette / pydantic v2 / SQLAlchemy asyncio / asyncpg / pgvector / httpx / PyYAML / pytest / numpy
- Python 3.11.15,venv 隔离

## 遇到的问题报错及解决方法

1. **pip 默认镜像(清华 tuna)读超时**:`ReadTimeoutError ... pypi.tuna.tsinghua.edu.cn`,导致 `No matching distribution found for fastapi`。
   解决:改用官方源 `pip install -i https://pypi.org/simple --timeout 60`,一次装齐全部 35 个包。
2. **PowerShell 把 pip 的 stderr notice 误判为失败**(NativeCommandError):pip 实际输出 `Successfully installed ...`,仅因向 stderr 写了升级提示导致退出码非 0。
   解决:用 `python -c "import fastapi, ..."` 直接验证依赖可导入,确认安装真实成功。

## 上下游接口及依赖

- 上游:无
- 下游:所有模块依赖 `app.config.get_settings()` 取配置;`app.main:app` 是后续所有 API 路由(/agent/chat 等)的挂载点
- 对外接口:`GET /health` → `{status, service, version, llm_mock, embedding_mock}`
