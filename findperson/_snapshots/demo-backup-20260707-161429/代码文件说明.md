# 首问责任平台代码文件说明

这份文档只说明当前仓库里的代码文件，方便上传到 GitHub 后让协作者快速看懂项目结构。

## 一、当前有哪些代码文件

当前真正承载页面功能的代码文件只有 3 个：

1. `index.html`
2. `assets/main.css`
3. `assets/main.js`

除此之外，仓库里还有以下非代码文件：

- `README.md`：项目说明
- `首问责任平台实施方案.md`：方案文档
- `首问责任平台建设方案.docx`：方案原始文档
- `首问责任平台方案v2.docx`：历史方案文档
- `assets/logo.png`：页面使用的 logo 图片
- `.gitignore`：Git 忽略规则

## 二、每个代码文件分别负责什么

### 1. `index.html`

这是页面入口文件，负责放置整个静态 Demo 的 DOM 结构。

当前主要包含这些页面区域：

- 左侧导航：智能问答、名片库、个人中心、后台管理
- 顶部用户入口：头像、个人中心、修改密码、操作手册、退出登录
- 登录页
- 智能问答页
- 历史对话侧栏
- 右侧详情栏
- 名片库页面
- 个人中心页面
- 后台管理页面

你可以把它理解成“页面骨架文件”。它本身不处理业务逻辑，主要负责给 `assets/main.js` 提供可操作的页面节点。

### 2. `assets/main.css`

这是样式文件，负责整个 Demo 的视觉表现和布局。

当前主要承担这些职责：

- 定义全局颜色、圆角、阴影、字体等设计变量
- 定义整体布局：左侧导航 + 主内容区
- 定义问答区、名片库、详情栏、个人中心、后台看板等模块样式
- 定义按钮、表单、卡片、弹层、列表等通用组件样式
- 处理页面在当前 Demo 中的视觉统一性

如果后续有人要改界面风格，主要会在这个文件里动。

### 3. `assets/main.js`

这是当前项目最核心的代码文件，负责所有前端交互逻辑和本地模拟数据。

它当前做了几类事情：

- 定义本地模拟数据
- 管理页面状态
- 处理导航切换
- 处理问答输入与推荐结果
- 处理历史会话
- 处理名片库搜索与筛选
- 处理个人资料编辑
- 处理内容发布、内容检索、内容详情
- 处理他画像评价
- 处理后台统计看板
- 通过 `localStorage` 保存本地数据

这个文件相当于当前 Demo 的“前端单文件应用逻辑中心”。

## 三、`assets/main.js` 里的代码块怎么理解

为了让协作者更快上手，可以把 `assets/main.js` 大致分成下面几层。

### 1. 数据与配置

文件开头主要是一些基础数据和配置：

- `STORAGE_KEYS`：本地存储 key
- `seedPeople`：模拟人员数据
- `seedContent`：模拟内容数据
- `manualSections`：操作手册内容
- `domainDictionary`：关键词和领域词映射
- `state`：页面运行时状态
- `viewTitles`：各页面标题映射

这部分决定了当前 Demo “默认展示什么数据”。

### 2. 初始化逻辑

入口是：

```js
document.addEventListener("DOMContentLoaded", init);
```

`init()` 会统一做这些事情：

- 初始化会话
- 初始化当前用户资料
- 绑定各类事件
- 渲染问答、名片库、个人中心、后台等内容
- 恢复默认页面视图

这部分是页面启动主链路。

### 3. 页面切换与导航

这部分函数负责“去哪一个页面”：

- `bindNavigation()`
- `navigateTo()`
- `applyRoute()`
- `switchView()`
- `bindAvatarEntry()`
- `bindAvatarMenu()`

如果后面要继续加页面，通常会从这里接入。

### 4. 智能问答主链路

这是这个 Demo 最关键的一段逻辑，主要函数包括：

- `bindQuestion()`
- `runCurrentQuestion()`
- `matchQuestion()`
- `analyzeQuestion()`
- `extractTokens()`
- `inferIntent()`
- `buildAssistantAction()`
- `matchContent()`
- `scorePerson()`

这一层做的事是：

1. 获取用户输入的问题
2. 识别问题意图
3. 提取关键词
4. 匹配相关内容
5. 匹配相关人员
6. 生成推荐结果和推荐理由
7. 把结果渲染到对话区

如果以后要接后端接口或大模型接口，这一段最值得优先改造。

### 5. 历史会话与本地状态

这部分负责问答历史记录：

- `ensureSessions()`
- `createSession()`
- `loadSessionIntoState()`
- `syncStateToActiveSession()`
- `renderConversationHistory()`
- `renderConversationSearchResults()`
- `selectConversationSession()`
- `editSessionTitle()`
- `softDeleteSession()`

现在这些数据都保存在浏览器本地，不是后端真实会话系统。

### 6. 名片库与人员主页

这部分负责人员相关页面：

- `bindDirectory()`
- `renderDepartmentFilters()`
- `renderDirectory()`
- `renderProfile()`

它支撑的是：

- 名片库列表展示
- 三级部门筛选
- 关键词搜索
- 人员主页展示

### 7. 个人中心、内容发布与评价

这部分负责“用户自己维护数据”的页面能力：

- `bindMineForm()`
- `renderMineSummary()`
- `bindPeerReviewForm()`
- `renderPeerReviewList()`
- `bindContentForm()`
- `renderContentSearch()`
- `openContentDetail()`
- `renderContentDetail()`

它覆盖的是：

- 修改个人资料
- 查看我发布的内容
- 发布内容
- 搜索内容
- 查看内容详情
- 给别人补充评价

### 8. 后台看板

后台展示逻辑主要在：

- `renderAdmin()`
- `renderRankItem()`
- `buildWeeklyActiveTrend()`

当前后台数据也是模拟生成的，属于演示型看板，不是实时运营后台。

### 9. 本地存储与工具函数

文件后半部分还有一批通用函数，主要用于数据读写和小工具处理，例如：

- `loadContent()` / `saveContent()`
- `loadPeerReviews()` / `savePeerReviews()`
- `loadSessions()` / `saveSessions()`
- `loadAuth()` / `saveAuth()`
- `readJson()`
- `normalize()`
- `splitTags()`
- `escapeHtml()`

这一层是整个 Demo 的基础支撑。

## 四、协作者第一次接手时建议先看什么

如果是第一次接手这个项目，建议按下面顺序看代码：

1. 先看 `README.md`，了解这是一个静态前端 Demo
2. 再看 `index.html`，知道页面有哪些模块
3. 再看 `assets/main.js` 开头的数据区和 `init()`，理解页面启动主链路
4. 然后重点看问答主链路：`runCurrentQuestion()` 到 `scorePerson()`
5. 最后按需要去看名片库、个人中心、内容发布、后台看板这些分支逻辑

## 五、当前代码结构的真实状态

当前项目是一个单页静态 Demo，不是前后端分离工程。

它的特点是：

- 没有构建工具
- 没有框架
- 没有后端接口
- 没有模块化拆分
- 所有前端逻辑集中在 `assets/main.js`
- 所有样式集中在 `assets/main.css`
- 所有数据默认来自本地模拟数据和浏览器 `localStorage`

这意味着它很适合做原型展示，但如果后续多人共创、继续开发，下一步通常会是：

- 拆分 `main.js`
- 抽离模拟数据
- 增加 API 层
- 把本地存储逐步替换为后端数据

## 六、一句话总结

当前仓库的代码主体非常集中：`index.html` 管结构，`assets/main.css` 管样式，`assets/main.js` 管全部交互和模拟数据。
